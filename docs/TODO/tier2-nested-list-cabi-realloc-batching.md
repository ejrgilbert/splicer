# Tier-2 nested list: batch per-call `cabi_realloc`s

## Problem

Today, lifting `list<list<T>>` calls the inner list's
`cabi_realloc` once per outer iteration for each per-call buffer the
inner uses. For `outer.len = N` outer elements with K per-call
buffers per inner list, that is `N * K` realloc calls. The dominant
runtime cost for hot-path nested lists.

The five per-call buffers in `emit_list_of_arm`
(`src/adapter/tier2/lift/emit.rs`):

| Buffer | When allocated | Used by inner-T |
|---|---|---|
| `indices_ptr` | always | every inner T |
| `char_scratch_base` | inner has `Cell::Char` | char / option<char> / tuple<…, char> / etc. |
| `tuple_idx_buf_base` | inner has `Cell::TupleOf` | tuple / option<tuple> / etc. |
| `flags_scratch_buf_base` | inner has `Cell::Flags` | gated out today |
| `record_tuples_buf_base` | inner has `Cell::RecordOf` | gated out today |

For the depth-2 nested-list scope only the first three are reachable
(inner T must be on the per-call-buffer-free subset, per
`Cell::ListOf::list_element_class`).

## Fix sketch

One batched allocation per buffer, sized for the entire outer pass;
per-iter offset arithmetic for the inner's buffer base.

1. **Pre-pass accumulator.** `emit_nested_list_pre_pass`
   (`src/adapter/tier2/lift/emit.rs::1255`) already walks outer
   memory to read each `inner.len`. Sum these into a new local
   `nested_total_inner_len` while bumping `next_cell_idx`.
2. **Batched allocs.** After the pre-pass j-loop, `cabi_realloc`
   each batched buffer with `nested_total_inner_len * stride` bytes.
   Store bases in new `ListEmitLocals.nested_inner_*_buf_base`
   wrapper-locals.
3. **Per-iter offset.** Outer's `emit_list_of_arm` element-loop:
   before invoking inner emit, write
   `inner_ll.indices_ptr = batched_indices_base + cursor * 4` (and
   same for char/tuple if applicable). Advance the cursor by
   `inner.len` at iter-end (parallel to the existing
   `nested_inner_cursor` which tracks cell-array position).
4. **Skip inner's per-call allocs.** Either:
   - **(a) Skip flag.** Add `pre_allocated_buffers: bool` parameter
     to `emit_list_of_arm`; nested caller passes `true`.
   - **(b) Helper split.** Hoist the per-call `cabi_realloc` calls
     into `emit_list_of_per_call_allocs(f, ctx, ll)`. Top-level
     callers invoke it before `emit_list_of_arm`; nested callers
     skip it (buffers pre-computed). Cleaner; no mode flag.

   (b) is the recommended split.

## Cost / benefit

| Inner T | Today (N=1000) | After batching |
|---|---|---|
| scalar / option / result / enum | 1000 reallocs | 1 realloc |
| char | 2000 reallocs | 2 reallocs |
| tuple | 2000 reallocs | 2 reallocs |

`cabi_realloc` is a moderate-cost wasm call (host bookkeeping +
allocator path). 1000 → 1 is meaningful for hot paths.

Implementation cost: ~80–100 LOC across `emit.rs`. New wrapper-
locals (3–4 per nested list), pre-pass accumulator, per-iter offset
setup, helper-split refactor. No new wasm semantics — just shuffled
realloc points.

## Adjacent: inner-`len` double-load

`emit_nested_list_pre_pass` loads each `inner.len` from outer memory
once to size the cell slab. The main outer loop's `elem_loads`
(generated by `lift_from_memory` for the outer's `list<T>` element
type) re-reads the same `(ptr, len)` per outer element. Two memory
loads where one would suffice.

The dedupe options are awkward today: a single local doesn't work
(value differs per outer element); a per-element side buffer trades
memory traffic 1:1 (1 load + 1 store ↔ 1 load); a two-phase emit
that captures all outer state into side buffers, then allocates the
cell slab, then emits, would dedupe cleanly but restructures the
top-level pipeline.

Revisit after the batching work above lands — both touch the same
pre-pass walk and may share the same restructuring.

## Out of scope until landed

Even broader batching: when multiple separate top-level lists share
an inner element kind, their per-call buffers could in principle
share a slab. Probably not worth the cross-list bookkeeping; revisit
only if profiling shows it.
